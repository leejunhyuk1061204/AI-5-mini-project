# 통합 테스트 시나리오 및 1인용 대본 (Global 검색 특화)

이 문서는 **UI 통합(6번)**, **회의 히스토리(7번)**, 그리고 **녹음 수동 제어(8번)** 기능을 혼자서도 효과적으로 검증할 수 있도록 구성된 테스트 가이드입니다.

---

## 📋 테스트 준비 사항
1. **서버 확인**: 백엔드(`8080`) 및 AI 서버(`8001`)가 정상 실행 중인지 확인하세요.
2. **로그인**: 테스트 계정으로 로그인되어 있어야 합니다.

---

## 🧪 시나리오: 단계별 통합 테스트

### 1단계: 과거 데이터 구축 (대본 A 사용)
*목표: 나중에 검색될 '과거 기록'을 먼저 생성합니다.*
1. **실시간 회의록** 페이지에서 녹음을 시작합니다.
2. 하단의 **[대본 A]**를 천천히 읽습니다.
- [x] 전사 및 요약 품질 개선 작업
    - [x] 기술 용어 오인식 교정 필터 적용 (박백업 -> 백엔드 등)
    - [x] Whisper 반복 문구 제거 로직 구현
    - [x] 실시간 요약 환각(Hallucination) 방지 및 프롬프트 고도화
- [x] 실시간 요약 UI 최종 폴리싱
    - [x] 내부 제목 및 구분선 제거로 초간결화
    - [x] 알림 및 안내 문구 최적 배치 (박스 외부로 분리)
4. **[AI 요약하기]**를 눌러 결과가 잘 나오는지 확인합니다.
    - **핵심**: '빠른 요약' 기능이 적용되어 **5~10초 내외**로 요약이 완료되어야 합니다. (이 단계에서는 화자 분리 없이 텍스트만 요약됩니다.)
5. **[저장하기]**를 눌러 세션을 종료합니다.
    - **참고**: 이 버튼을 누르면 전체 오디오에 대한 **정밀 분석(화자 분리 포함)**이 백그라운드에서 진행됩니다.

### 2단계: 현재 회의 및 Global 검색 (대본 B 사용)
*목표: 현재 회의 중에 과거 데이터를 챗봇으로 찾아봅니다.*
1. 다시 **실시간 회의록** 페이지에서 새 녹음을 시작합니다.
2. 하단의 **[대본 B]**를 읽습니다.
3. 녹음 중이거나 중지된 상태에서 우측 **AI 챗봇**을 엽니다.
4. **'Global'** 토글을 켭니다.
5. **질문**: "우리 프로젝트에서 사용하는 데이터베이스는 뭐야?"라고 묻습니다.
6. **검증**: 대본 B에는 DB 정보가 없지만, 챗봇이 대본 A의 내용을 바탕으로 "MySQL 9.5 Vector"라고 답하는지 확인합니다.

### 3단계: 히스토리 관리 및 삭제
1. **'회의 히스토리'** 페이지로 이동합니다.
2. 대본 A와 대본 B로 저장된 회의가 목록에 나란히 있는지 확인합니다.
3. 목록에서 하나를 삭제하고, 목록 및 상세 뷰가 정상적으로 갱신되는지 확인합니다.

## 💬 1인 테스트용 대본

### [대본 A: 과거 회의 - '기술 스택 선정']
> "이번 프로젝트의 핵심 기술 스택을 정리합니다. 백엔드는 Java Spring Boot를 사용하고, AI 엔진은 Python FastAPI로 구축했습니다. 데이터베이스는 가장 중요한 결정 사항인데, 벡터 검색을 위해 **MySQL 9.5 버전의 Vector 타입**을 도입하기로 했습니다. 임베딩 모델은 KR-SBERT를 사용하여 768차원 벡터를 저장할 예정입니다."

### [대본 B: 현재 회의 - '홍보 및 출시 전략']
> "현재 진행 중인 출시 전략 회의입니다. 정식 서비스 출시는 이번 달 말일로 확정되었습니다. 단기적으로는 유튜브 쇼츠와 인스타그램 광고를 통해 인지도를 높일 계획입니다. 또한, 초기 사용자 1,000명에게는 프리미엄 기능을 한 달간 무료로 제공하는 프로모션을 진행하겠습니다."
